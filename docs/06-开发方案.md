## 0. 结论摘要

| 项 | 决定 |
|---|---|
| 路线 | **保留 Core（改名 `TypetodoCore`）+ 新增 Todo 子系统 + P0 内做一次页面对象化** |
| 新增代码量 | Core ≈ 2,600 行，App ≈ 3,200 行，测试 ≈ 1,400 行 |
| 重构老代码 | `SettingsWindowController` 6,828 行拆为 1 个壳 + 8 个页面 + 组件目录（行为不变） |
| 接线改动 | 6 个文件、约 180 行（不含页面搬迁） |
| 工期 | **34 人日**（P0 10 + P1~P6 24）。AI 协作下实际约 3~5 个工作日 |
| 最大风险 | ① 页面搬迁导致 selector 断链 ② `⌘` 手势误触 ③ 时间解析准确率 |

**核心策略**：先删（商业化 889 行）→ 再拆（页面对象化，静态检查兜底）→ 后加（新功能全部落在新文件）。

### 2.1 依赖规则（Code Review 必查）

1. Core 不得 `import AppKit` / `UserNotifications` / `ApplicationServices`
2. App 不得直接拼 prompt 或写 SQL，一律走 Core 类型
3. 页面不得互相调用；共用样式走 `DS.swift`，共用状态走 `PageContext`
4. 单文件 ≤ 400 行（老文件在拆分完成前豁免）

### 3.5 重构期静态检查（关键）

拆分最怕"按钮点了没反应"。`tools/check_app_invariants.py` 检查两件事：

1. 每个本地 `#selector(x)` 都能找到对应的 `@objc` / `override` 方法
2. `Page` 的每个 case 都有 build 分支

**基线（改动前实测）**：19 个文件 / 116 个本地 selector / 0 孤儿 / 8 个页面全有分支。
**P0 删除反馈/客服链路与商业化 UI 后**：18 个文件 / 98 个 selector / 0 孤儿 / 7 个页面全有分支。

每一步搬迁后重跑，退出码必须为 0。这是唯一能自动发现 selector 断链的手段。

## 4. 关键模块设计

### 4.1 手势路由

```swift
// Core: Capture/InputRegion.swift
public enum InputRegion: Equatable { case editable, askable, blocked, unknown }

// Core: Capture/GestureRouter.swift
public enum CaptureIntent: Equatable { case dictation, askAI, todo }

public struct GestureSettings: Equatable {
    public var dictationEnabled: Bool
    public var askEnabled: Bool
    public var todoEnabled: Bool
}

public enum GestureRouter {
    public static func route(region: InputRegion,
                             commandHeld: Bool,
                             settings: GestureSettings) -> CaptureIntent? {
        switch (region, commandHeld) {
        case (.editable, false): return settings.dictationEnabled ? .dictation : nil
        case (.editable, true):  return nil                  // 输入框内不启用 ⌘
        case (.askable, false):  return settings.askEnabled ? .askAI : nil
        case (.askable, true),
             (.unknown, true):   return settings.todoEnabled ? .todo : nil
        case (.unknown, false), (.blocked, _): return nil
        }
    }
}
```

- `TextInputVerdict → InputRegion` 的映射写在 App 层，Core 不反向依赖
- 阈值：`⌘` 路径 0.55s，普通左键 0.45s
- 只在按下瞬间采样 ⌘，不支持中途补按
- 单测覆盖 10 种组合

### 4.2 捕获编排

```swift
final class CaptureCoordinator {
    struct Deps {
        let recorder: AudioRecorder
        let transcriber: SpeechRecognizing
        let extractor: TodoExtracting
        let todos: TodoRepository
        let lists: ListRepository
        let reminders: ReminderScheduling
        let clock: () -> Date
        let timeZone: () -> TimeZone
    }

    func begin() -> Bool
    func finish() async
    func cancel()
    var onState: ((CaptureState) -> Void)?
}
```

时序与三条降级：

```
begin: recorder.start → .listening → 胶囊
finish: stop → samples
        → transcriber → .recognizing
        → 空文本 → .failed(.noSpeech)
        → extractor → .extracting
        → validator → 分拣
        → repository.insert(batchId) → reminders.reschedule()
        → .added(n)
```

**撤销（FR-13）**：入库返回 `(batchId, ids)`，`CaptureCoordinator` 持有 `UndoToken`，胶囊切到「已添加 N 条」并启动 5s 计时；点撤销 → `repository.deleteBatch(batchId)` → 广播变更；计时器到点释放 token。

**取消**：Esc 或时长 <0.8s → `cancel()` → 丢弃 samples、不落库、胶囊收起。

**并发**：`finish` 在 `Task` 中执行，UI 回调回主线程；复用上游 `activeEntryID` 令牌丢弃晚到结果。

**超时**：ASR 8s、抽取 8s，各自独立；超时走 E1/E3 降级。

### 4.3 解析链路

```swift
public struct ExtractionContext {
    public let now: Date
    public let timeZone: TimeZone
    public let availableLists: [String]
}

public protocol TodoExtracting {
    func extract(_ transcript: String, context: ExtractionContext) async throws -> [TodoDraft]
}

public struct TodoDraft: Equatable {
    public var title: String
    public var dueAt: Date?
    public var dueHasTime: Bool
    public var listName: String?
    public var confidence: Double
}
```

`LLMTodoExtractor` 要点：

| 项 | 取值 |
|---|---|
| 端点 | 复用已配 provider（Qwen / GLM / 豆包） |
| 请求体 | `response_format: json_object`、`temperature 0.1`、`max_tokens 800` |
| prompt | 角色 + schema + 4 个 few-shot + `now`/`tz`/`lists` |
| 超时 | 8s |
| 重试 | 仅 JSON 非法重试 1 次（回灌错误）；网络/403 不重试 |
| 降级 | 返回单条 `TodoDraft(title: 原文, dueAt: nil, confidence: 0.3)` |

提示词骨架：

```
你是待办抽取器。输入是一段口语转写，输出 JSON。
当前时间：{now ISO8601}（{weekday}，{tz}）
用户已有清单：{lists}

规则：
1. 多件事拆多条；只为"要做的事"建条目，寒暄/感慨不建。
2. 时间换算成绝对时间，ISO8601 带时区；说不清输出 null，不要猜。
3. 时间缺失时 due_has_time=false。
4. list 只能是给出的清单名之一，否则 null。
5. 标题 ≤ 20 字，动词开头，去掉"帮我/记得/那个"。
6. confidence：时间明确 0.9；只有标题 0.6；含糊 0.4。

输出：{"todos":[{"title":"","due_at":null,"due_has_time":false,"list":null,"confidence":0.0}]}
```

校验三层：

1. 结构：title 非空、≤40 字、confidence ∈ [0,1]
2. 时间：`dueAt ∈ [now-1d, now+2y]`；含"明天/后天/下周X"时与 `TimeNormalizer` 推算比对
3. 归属：`listName` 不在已有清单 → 置 nil

### 4.4 数据层

```swift
public final class Database: @unchecked Sendable {
    public init(path: String) throws
    public func migrate() throws
    public func write<T>(_ body: (OpaquePointer) throws -> T) throws -> T
    public func read<T>(_ body: (OpaquePointer) throws -> T) throws -> T
}
```

- 单连接 + 串行队列 + `SQLITE_OPEN_FULLMUTEX` + WAL
- 迁移：`PRAGMA user_version` + 有序数组，事务包裹，失败回滚保留旧库
- 幂等：`dedupe_key` 唯一索引 + `ON CONFLICT DO UPDATE`
- 查询下推：视图过滤写进 WHERE，禁止内存过滤

```sql
SELECT * FROM todo
WHERE status = 0 AND due_at IS NOT NULL AND due_at < :endOfToday
ORDER BY due_at;
```

**清理任务**（启动时执行一次）：`status=1 且 completed_at < now-7d` 物理删除；`status=2 且 deleted_at < now-7d` 物理删除；对应 `audio_ref` 一并删文件。

### 4.5 提醒

```swift
public enum ReminderPlanner {
```

## 6. 关键流程

### 6.1 捕获

```
⌘ 按住 0.55s
  ├─ 区域不合法 / 设置关闭 → 不动作
  └─ 录音
松手
  ├─ <0.8s 或 Esc → 丢弃
  ├─ ASR 失败 → 存音频进历史 → "识别失败，可重试"
  └─ ASR 成功
       ├─ 抽取失败（重试 1 次后）→ 原文入库 needs_tidy
       └─ 抽取成功
            ├─ 全高置信 → 入库 → "已添加 N 条" → 5s 撤销
            └─ 含低置信 → 确认卡 → 入库
```

见 §4.5。重建失败只记日志，不阻断业务。

## 10. 风险与对策

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 页面搬迁导致 selector 断链 | 静态检查非 0，或某按钮无反应 | 每步搬迁后跑脚本；单页单 commit；先搬最小页面验证模板 |
| 搬迁引发布局/时序问题 | RG-09 某页错位或空白 | 一次只搬一页；壳的时序保持原顺序；不合并"搬家 + 改逻辑" |
| `⌘` 手势误触超标 | P3 真机 >1/20 | 收窄到 `.askable`；仍超标降级为 `⌥Space` |
| 时间解析准确率 <80% | P2 首轮评测 | 加 few-shot；相对时间改本地规则算 |
| 老功能回归 | RG-01~08 任一失败 | 改动前跑基线；每处单独 commit |
| SQLite 线程问题 | `SQLITE_BUSY` / 崩溃 | 单连接串行 + WAL；禁止跨线程持有 statement |
| 通知在 ad-hoc 下不弹 | 收不到横幅 | 固定 bundle id；装 `/Applications`；`lsregister -f` |

## 11. 回答 PRD 附录 15.2 的七个问题

1. **模块拆分与文件规划** — 见 §3.1。新增约 42 个文件；页面拆分后单页 ≤900 行，其余 ≤400。
2. **Core / App 边界** — Core 只允许 `Foundation`/`SQLite3`/`Security`；UI、通知、AX、剪贴板在 App。判断标准：能在没有窗口的情况下单测的，一律进 Core。
3. **数据库迁移** — `user_version` + 有序 migration，事务包裹；失败回滚并保留旧库，启动提示。
4. **`⌘` 手势位置** — 采样在 `MouseHoldToTalkManager`，决策在 Core `GestureRouter`，执行在 `CaptureCoordinator`；原 ask 分支语义不变。
5. **解析可观测性** — 日志字段 `entryId/elapsedMs/charCount/retryCount/errorCode/draftsCount/confidence[]`，写 `~/Library/Application Support/Typetodo/parse.log`，按 2MB 轮转，不记正文。
6. **二期切换点** — `AppComposition.make()` 是唯一注入点；替换 `TodoExtracting`/`SpeechRecognizing` 实现即可，UI 与仓储零改动。
7. **里程碑** — 见 §9。
