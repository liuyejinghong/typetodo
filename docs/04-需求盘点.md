## 二、产品一句话

**Typetodo = 一个能听懂你说话的待办清单。** 按住 `⌘` 说一句，它变成（或几条）带时间的待办；在输入框里按住，它还是原来那个顺手的语音输入法。

---

## 三、信息架构（Q4 定稿）

采用主流待办产品的双层结构：**智能视图（按时间自动聚合）× 清单（按归属手动归类）**。

```
侧栏
├── 收件箱        无日期的待办
├── 今天          逾期 + 今天到期
├── 即将          未来 7 天，按天分组
├── 清单          可自建（工作 / 生活 / …）
└── 底部          已完成 · 设置
```

### 为什么保留「收件箱」

它不是清单，是**视图**——一条待办不会"属于收件箱"，只是在**没有时间**时出现在那里。存在的理由：

1. **语音捕获大概率不带时间**（"买咖啡""查一下那个报错"），需要一个不会被「今天/即将」过滤掉的落脚点。
2. 没有它，无日期项只能塞进「全部」，会被带时间的项淹没，也没法"回头再安排"。
3. Things、Todoist、滴答清单都是这个结构，用户不用重新学。
4. 它天然对上一个动作：**定期清空收件箱**（给每项补时间或归到清单），这是待办产品的核心习惯。

### 两条轴的关系

| 轴 | 决定什么 | 例子 |
|---|---|---|
| 时间（智能视图） | 一条待办**什么时候被看到** | 「明天 15:00 交周报」→ 今天不出现，明天出现在「今天」 |
| 归属（清单） | 一条待办**属于哪摊事** | 同一条同时在「工作」清单里 |

一条待办的字段只有三个：**标题、时间（可空）、清单（可空）**。

- 有时间 → 进「今天 / 即将」
- 没时间 → 进「收件箱」
- 有清单 → 同时在该清单下可见
- 没清单 → 只出现在智能视图（收件箱 / 今天 / 即将）

### 逾期怎么处理

「今天」= 逾期 + 今日到期。逾期项单独分组置顶，标红点，不做单独的「逾期」入口——多一个入口就多一次决策。

## 六、关键流程与边界

### 6.1 一句话 → N 条待办

```
语音 → 识别原文 → 结构化抽取（返回数组）→ 逐条校验 → 批量入库 → 反馈
                                      ↘ 校验失败 → 原文当标题入库，标"待整理"
```

### 6.2 自动拆分的规则（Q2）

| 情况 | 表现 |
|---|---|
| 一句话一件事，带时间 | 生成 1 条带时间待办 |
| 一句话一件事，没时间 | 生成 1 条，进收件箱 |
| 一句话三件事 | 拆成 3 条；胶囊显示「已添加 3 条」，可展开看 |
| 拆分后某条缺时间 | 该条进收件箱，其余正常 |
| 拆错了（把一句话拆成两条） | 撤销后一次性回滚整批 |

**硬约束**：拆分产生的多条共享同一个 `batch_id`，一次撤销整批回滚，不做"逐条撤销"——逐条撤会让用户算不清撤了哪几条。

### 6.3 置信度的判定（Q3）

| 条件 | 行为 |
|---|---|
| 标题非空 + 时间解析成功 + 置信度 ≥ 0.8 | 直接入库 + Toast（5 秒撤销） |
| 标题为空 / 时间歧义（"过几天"）/ 置信度低 | 弹确认卡，字段可编辑 |
| 模型返回非法 JSON / 网络失败 | 原文当标题入库，标"待整理"，不打断 |

### 6.4 待办状态

`待办 → 完成`（可撤销）→ 进「已完成」，保留 7 天后自动清理。删除为软删。**不做归档。**

## 七、原型要验证的五个问题

| # | 假设 | 怎么验 | 用什么 |
|---|---|---|---|
| **P1** | `⌘`+长按在浏览器/编辑器/终端不误触 | 真机各按 20 次，记录副作用 | Swift spike（不是 HTML） |
| **P2** | 一句话的结构化结果准不准 | 20 句真实口述，含相对时间/多任务/含糊表达 | 提示词脚本 + 人工评分 |
| **P3** | 「直接入库 + 撤销」是否比确认卡更顺 | 两种流程对比走查 | HTML 可点击原型 |
| **P4** | 三个智能视图 + 清单的信息密度 | 20 条数据下能否一眼扫完 | HTML 可点击原型 |
| **P5** | 提醒的打扰程度与动作按钮 | 横幅文案 + 完成/稍后 | HTML 模拟 + 真机通知 |

### 推进方式：并行，不是先后

界面原型与解析验证**互不依赖**，可以同时进行：

| 线 | 内容 | 依赖 | 产出 |
|---|---|---|---|
| **A 界面** | 可点击 HTML 原型：捕获态 / 今天 / 收件箱 / 详情（+ 通知模拟） | 无，随时可开 | 验 P3 入库反馈、P4 信息密度 |
| **B 解析** | 20 句样本 + 提示词 + 评分表 | 需要模型 API Key（从环境变量读） | 验 P2 字段准确率，决定"三字段"是否成立 |
| **C 手势** | Swift spike：真机测 ⌘+长按误触 | 需要 Xcode 与签名 | 验 P1，决定手势是否保留 |

**为什么仍要尽早跑 B**：不是为了排期，而是它决定原型的**最终形态**——如果模型给不出可靠的时间，原型里的「今天 / 即将」就是假的，产品要退回"语音记事本"。B 的结果不影响 A 先动工，但会影响 A 的第二版。
