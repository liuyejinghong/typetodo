### 2. `xcode-select` 仍指向 Command Line Tools

```
当前：/Library/Developer/CommandLineTools
应为：/Applications/Xcode.app/Contents/Developer
```

影响：`swift test` 找不到 XCTest（我之前是用 `DEVELOPER_DIR` 环境变量绕过的），`xcodebuild` 也需要每次带环境变量。

两种解法：

- 你执行一次 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`（一劳永逸）
- 或我在所有脚本里统一加 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`

我倾向第一种，命令只有一条，但要 sudo，得你来。

## 三、一个性能风险（首次构建）

实测网络：

| 路径 | 速度 |
|---|---|
| 直连 codeload | ~200 KB/s |
| 走系统代理 7897 | ~110 KB/s |
| 走环境代理 57919（当前会话注入） | ~110 KB/s |

`git clone Sparkle`（`--depth 1 --filter=blob:none`）跑了 8 分钟仍未完成，我中止了。Xcode 解析 SPM 依赖走的是同一条链路，**首次构建可能卡 5~15 分钟**。

对策（P0 执行）：

1. 首次先单独跑一次 `xcodebuild -resolvePackageDependencies` 把依赖拉下来，不跟主构建混在一起。
2. 之后所有构建都带 `-clonedSourcePackagesDirPath ~/Library/Caches/typetodo/spm`，复用缓存，不再联网。
3. 如果实在拉不动，再考虑把 Sparkle 换成本地路径引用（会偏离上游工程结构，非必要不做）。
