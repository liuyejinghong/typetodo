## 二、背景与目标

### 2.1 背景

上游 Typefree 是一个成熟的 macOS 语音输入工具：按住说话，松开后文字已由大模型整理好并粘贴到光标处。它的能力边界停在"把话变成文字"。

真实使用中还有一类高频需求没被满足：**说话时想记的是"一件事"，不是"一段话"**。"明天下午三点把周报发给张总" —— 用户要的不是一行字，是明天 15:00 会提醒他的一条待办。

### 2.2 目标

在**完整保留原听写能力**的前提下，新增"语音 → 结构化待办 → 本地清单 → 到点提醒"的闭环。

一句话：**一个能听懂你说话的待办清单。**

### 2.3 成功标准（一期无埋点，用离线评测 + 自用验收）

| 指标 | 目标 | 口径 |
|---|---|---|
| 结构化字段准确率 | ≥ 80% | 20 句评测集，标题/时间/拆分三项加权（标题 40%、时间 30%、拆分 20%、JSON 合法 10%） |
| 捕获端到端耗时 | P50 ≤ 2.0s，P95 ≤ 4.0s | 松手 → 胶囊显示"已添加" |
| 听写链路不退化 | 与原版一致 | 短句直出、术语纠正、粘贴与剪贴板还原三项回归通过 |
| 撤销率（自用观察） | ≤ 15% | 撤销次数 ÷ 创建次数，仅本地统计 |
| 崩溃与丢数据 | 0 例 | 任何失败路径都不得丢失用户语音原文 |

> 一期不做任何联网埋点。上面的"撤销率"从本地数据库统计，不上报。

## 三、名词与术语

| 术语 | 定义 |
|---|---|
| **听写** | 原版能力：语音 → 润色文本 → 粘贴到前台 App 光标处 |
| **捕获** | 新增能力：语音 → 结构化待办 → 入库 |
| **待办（Todo）** | 最小对象：标题 + 时间（可空）+ 清单（可空）+ 状态 |
| **清单（List）** | 待办的归属分类，可自建（工作/生活…） |
| **智能视图** | 按时间自动聚合的视图：收件箱 / 今天 / 即将 |
| **收件箱** | 无时间待办的视图，**不是清单** |
| **批次（Batch）** | 一次语音拆出的多条待办，共享 `batch_id`，整批撤销 |
| **胶囊** | 录音与结果反馈的悬浮控件（原版已有 `SiriCapsuleView`） |
| **自带 Key** | 用户自行填入的第三方模型 API Key，存本机钥匙串 |
| **托管通道** | 二期能力：走自有服务端转发，一期不存在 |

## 五、方案选型记录（已决策，供开发理解约束）

| 议题 | 结论 | 理由 |
|---|---|---|
| 授权路径 | **方案 A：跟随 GPL-3.0 开源** | 商业模式在服务端额度，不在代码；重写需 35~45 人日 |
| 改造策略 | **留核心、换外壳、加语义** | 核心库 `VoicePolishCore` 8,786 行可独立编译、299 测试全绿 |
| 手势 | **原版一律不动**，新增 `⌘ + 左键长按` | `⌘` 的副作用在 mouseUp 触发，长按可安全接管；右键在 mouseDown 即弹菜单，不可行 |
| 解析 | **一次 LLM 调用**（ASR → 抽取），不经过润色 | 润色是"改写"，对抽取无益且多 1~2s |
| 待办存储 | 系统 `libsqlite3`，不引第三方 | 与上游"零依赖"风格一致 |
| 信息架构 | 智能视图 × 清单 双层 | 主流待办产品结构，用户零学习成本 |

## 六、用户角色与场景

### 6.1 角色

| 角色 | 描述 | 关键诉求 |
|---|---|---|
| **主要用户（本人）** | macOS 重度用户，开发者/知识工作者，已在用语音输入 | 不打断当前工作，一句话记下，回头能处理 |
| 次要用户（同事/朋友） | 被推荐安装，自带 Key | 装完能用，不用读文档 |

不设管理员、不设多角色权限。

### 6.2 核心场景

**S1 捕获（最高频）**
> 开会时听到决定。按住 `⌘` + 鼠标左键说："明天下午三点把周报发给张总，顺便订一下下周三的会议室，还有记得买咖啡豆"。
> 松手 → 胶囊「已添加 3 条」→ 2 条进"即将"、1 条进"收件箱"。5 秒内可整批撤销。

**S2 听写（不得退化）**
> 写邮件时输入框里按住左键说一段，松手文字已整理好落在光标处。

**S3 处理**
> 傍晚打开待办页：「今天」里 2 条逾期置顶、3 条今日到期。勾掉两条，把一条改到明天。

**S4 提醒**
> 15:00 右上角弹横幅「交周报 · 今天 15:00 · 工作」，可直接点「完成」或「稍后 1 小时」。

## 七、功能需求

> 优先级：Must / Should / Could。验收标准用 Given/When/Then。

### 7.1 捕获与手势

#### FR-01 `⌘ + 左键长按` 捕获待办（Must）

- 触发条件：按住 `⌘`，在**非可点击区域**按下左键并保持 ≥ 0.55s
- 生效范围：`TextInputLocator` 判定为 `.askable` 与 `.unknown` 的区域
- 不生效：输入框/文本编辑区、按钮、链接、图片、列表行、视频画面
- 反馈：按下 `⌘` 时菜单栏图标进入待办态；达到阈值播放开始音；松手播放结束音

**验收**
- Given 我在浏览器正文区，When 按住 ⌘ 并按住左键 0.6s，Then 开始录音，胶囊出现，菜单栏图标为待办态
- Given 我在输入框内，When 按住 ⌘ 并按住左键 0.6s，Then **不触发**捕获（输入框内 ⌘+长按不启用）
- Given 我在链接上，When 按住 ⌘ 并按住左键 0.6s，Then 不触发捕获，松手后浏览器正常新开标签
- Given 我只按 ⌘ 未按鼠标，Then 不触发任何录音

#### FR-02 原版手势保持不变（Must）

输入框长按 = 听写；空白处长按 = 问 AI；`⌥Space` = 听写；三者行为、阈值、反馈与原版完全一致。

**验收**：原版手势的回归用例全部通过（见 FR-19）。

#### FR-03 捕获胶囊（Must）

三态：`录音中`（波形 + "正在听…" + "松开结束"）→ `处理中`（转圈 + "识别中…"/"整理成待办…"）→ `结果`（"已添加 N 条"）。

**验收**
- Given 录音中，When 松手，Then 胶囊 200ms 内切换到处理中
- Given 解析成功，When 入库完成，Then 胶囊显示"已添加 N 条"，2.5s 后自动消失
- Given 解析失败，Then 胶囊显示"已存为待办 · 待整理"，不报错弹窗

#### FR-04 取消与误触（Must）

- 录音中按 Esc → 取消，不产生待办
- 按住期间指针移动 > 6pt → 视为拖拽，不触发
- 按住 < 0.55s 松手 → 不触发；若已开始录音但时长 < 0.8s → 丢弃并提示"太短了"

**验收**：Given 我按了 0.3s 就松手，Then 不产生待办、不弹胶囊、无提示音

### 7.2 结构化解析

#### FR-05 语音 → 待办 JSON（Must）

一次 `chat/completions` 调用，返回数组：

```json
{
  "todos": [
    {
      "title": "把周报发给张总",
      "due_at": "2026-10-27T15:00:00+08:00",
      "due_has_time": true,
      "list": "工作",
      "confidence": 0.86
    }
  ],
  "raw_summary": "一句话里提到三件事"
}
```

规则：
- `title` 必填，≤ 40 字，去句末标点
- `due_at` 为 ISO8601 带时区；无时间为 `null`，`due_has_time=false`
- `list` 必须是用户已有清单名之一，否则置 `null`
- `confidence` 0~1

**验收**
- Given 说"明天下午三点把周报发给张总"，Then 返回 1 条，`due_at` = 次日 15:00，`list` ∈ 已有清单
- Given 说"买咖啡豆"，Then 返回 1 条，`due_at=null`
- Given 模型返回非法 JSON，Then 系统重试一次；仍失败则原文当标题入库并标 `needs_tidy=true`

#### FR-06 提示词上下文注入（Must）

请求必须包含：`now`（ISO8601 + 星期）、时区、用户已有清单名、当前语言。缺任一项视为实现缺陷。

**验收**：抓包可见 system prompt 内含当次 `now` 与清单列表

#### FR-07 多任务自动拆分（Must）

一句话含多件事时拆成多条，共享同一 `batch_id`，整批撤销。

**验收**
- Given 说"明天交周报、后天开会、买咖啡豆"，Then 生成 3 条，`batch_id` 相同，胶囊显示"已添加 3 条"
- Given 我对这 3 条点撤销，Then 3 条全部消失，不残留
- Given 其中一条时间缺失，Then 该条进收件箱，其余不受影响

#### FR-08 时间归一化校验（Must）

模型输出的时间不直接采信，本地二次校验：
- `due_at` 必须在 `[now - 1天, now + 2年]` 内
- 相对时间交叉核对（"明天"必须等于 now + 1 天，"下周X"必须落在下周）
- 校验失败 → `confidence` 降为 0.5 并置 `needs_confirmation=true`

**验收**：Given 模型把"明天"算成今天，Then 系统纠正为明天；无法纠正时进入确认卡

#### FR-09 置信度与入库策略（Must）

| 条件 | 行为 |
|---|---|
| `confidence ≥ 0.8` 且 title 非空 | 直接入库 + 胶囊「已添加」+ 5 秒撤销 |
| `confidence < 0.8` 或时间歧义 | 弹确认卡，字段可编辑，确认后入库 |
| JSON 非法/网络失败 | 原文当标题入库，标 `needs_tidy`，提示"已存为待办 · 待整理" |

**验收**：Given "过几天找李工聊接口"，Then 弹确认卡，时间字段为空并提示"未识别到具体时间"

### 7.3 待办管理

#### FR-10 待办页与视图（Must）

侧栏「工作台 → 待办」进入。页内分段：**今天 / 收件箱 / 即将 / 已完成**。

| 视图 | 规则 |
|---|---|
| 今天 | 逾期（分组置顶、标红）+ 今日到期；无逾期时不显示逾期分组 |
| 收件箱 | `due_at = null` 且未完成 |
| 即将 | 未来 7 天，按天分组升序 |
| 已完成 | 最近 7 天完成项 |

**验收**
- Given 有 2 条逾期 3 条今日，When 打开待办页，Then 显示"已逾期 2"与"今天 3"，逾期在前
- Given 一条待办今天 15:00 到期，When 现在是 16:00，Then 它出现在"已逾期"分组，时间标红

#### FR-11 清单管理（Must）

- 侧栏新增第三组「清单」，列出用户清单（默认空，用户自建）
- 支持新建 / 重命名 / 删除；删除清单时其下待办不删除，只置 `list_id=null`
- 点击清单 → 待办页切换为该清单过滤视图

**验收**
- Given 我新建清单"工作"，Then 侧栏出现该清单，计数为 0
- Given 我删除清单"工作"（下面有 3 条待办），Then 清单消失，3 条待办仍在（`list_id` 为空），可在收件箱/今天找到

#### FR-12 待办编辑（Must）

点列表行展开：原始语音（只读）+ 标记完成 / 删除；点标题可编辑；点时间可改；点清单标签可改归属。

**验收**
- Given 我点一条待办，Then 行展开显示原始语音与操作，不跳页、不弹窗
- Given 我把时间改成明天，Then 它从"今天"移到"即将 · 明天"

#### FR-13 完成 / 删除 / 撤销（Must）

- 完成：勾选即完成，行变灰划线，1.5s 后移出当前视图；可在"已完成"恢复
- 删除：软删（`deleted_at`），不立刻清库
- 撤销：新建后 5 秒内可整批撤销

**验收**：Given 我完成一条待办，Then 它从"今天"消失、出现在"已完成"，计数同步更新

#### FR-14 首页「今日待办」卡片（Must）

首页新增卡片：显示今日待办数量 + 前 3 条（标题/时间/清单）+「查看全部 →」。点击行跳转待办页并定位。

**验收**：Given 有 5 条今日待办，Then 卡片显示"5"与前 3 条，点"查看全部"进入待办页"今天"

### 7.4 提醒

#### FR-15 本地通知排程（Must）

- 使用 `UNUserNotificationCenter`
- 只排未来 7 天、按 `due_at` 升序最近 **60 条**
- 全天任务在当天 **09:00** 提醒（可在设置改）
- 已过期未完成：启动时汇总为 1 条"你有 N 条待办已过期"
- 重建时机：启动、唤醒、增删改完成、时区变更、修改默认提醒时间（重建前 `removeAllPending`）
- identifier 固定为 `todo.<uuid>`，保证幂等

**验收**
- Given 我新建一条明天 15:00 的待办，Then 系统 pending 中出现 identifier 为 `todo.<id>` 的请求
- Given 我把它改到后天，Then 旧请求被移除，新请求时间为后天
- Given 我完成它，Then 对应 pending 请求被移除

#### FR-16 权限申请与降级（Must）

- 首次创建带时间的待办时才申请通知权限（不在首启弹）
- 被拒绝：不阻断创建；设置页显示"通知未开启 · 去系统设置"，并给出跳转链接
- 前台：实现 `willPresent` 返回 `[.banner, .sound]`，否则前台不显示

**验收**：Given 通知权限被拒，When 我创建一条待办，Then 待办正常入库，设置页出现未开启提示

#### FR-17 通知动作（Must）

横幅含「完成」「稍后 1 小时」，点击通知本体打开 App 并定位到该条。连续延后 3 次自动改为次日 09:00。

**验收**：Given 横幅出现，When 我点"完成"，Then 该待办标记完成、横幅收起、对应 pending 被移除

### 7.5 原版能力与品牌替换

#### FR-18 品牌与身份替换（Must）

| 项 | 原值 | 新值 |
|---|---|---|
| 显示名 | Typefree | Typetodo |
| Bundle ID | `com.voicepolish.app` | `app.typetodo.mac`（待定，需全局唯一） |

#### FR-19 原版功能回归（Must）

听写链路回归项：短句（≤10 字）直出、术语纠正、粘贴与剪贴板还原（0.6s）、微信输入框、失败保留可重试、历史加密读写。任一失败即视为不达标。

#### FR-20 页面增删（Must）

- **删除**「反馈」页与相关网络调用
- **删除**试用/会员：侧栏方案卡、模型页会员区、`LicenseManager`/`TrialManager` 的入口（代码可保留，UI 不可见）
- 新增「待办」页与侧栏「清单」组
- 首页新增「今日待办」卡；探索页手势说明改为三条

### 7.6 二期预留

#### FR-21 接口骨架（Must，仅协议与空实现）

| 协议 | 一期实现 | 二期实现 |
|---|---|---|
| `AccountProviding` | `AnonymousAccount`（恒 `.anonymous`） | 远程账号 |
| `QuotaReporting` | `NoopQuota`（仅本地计数） | 上报服务端 |
| `EntitlementProviding` | 全部 `true` | 按会员态返回 |
| `SpeechRecognizing` | 直连火山/百炼 | 经 `/v1/asr` |

## 九、业务流程与状态

### 9.1 Todo 状态机

```
            创建
              │
        ┌─────▼─────┐
        │  pending  │◄──── 撤销完成 ────┐
        └─────┬─────┘                  │
     完成 │   │ 删除                    │
          ▼   ▼                        │
   ┌────────┐ ┌──────────┐             │
   │ done   │ │ deleted  │             │
   └───┬────┘ └──────────┘             │
       └────── 恢复 ──────────────────┘
```

- `pending → done`：勾选；`done → pending`：在已完成里恢复
- `pending → deleted`：软删；`deleted` 不出现在任何视图，7 天后物理清理
- 时间变更不影响状态，只影响所属视图

### 9.2 捕获流程

```
⌘+长按 → 录音 → 松手 → ASR → LLM 抽取 → 本地校验
                                   ├ 通过 → 入库 → 胶囊结果 → 5s 撤销
                                   ├ 低置信 → 确认卡 → 入库
                                   └ 失败 → 原文入库(needs_tidy) → 提示"待整理"
```

### 9.3 通知排程流程

```
数据变更/启动/唤醒/时区变更
   → 计算未来 7 天窗口内 pending 待办
   → 按 due_at 排序取前 60
   → removeAllPending()
   → 逐条 add(todo.<uuid>, calendarTrigger)
   → 失败逐条记录（不阻断）
```

## 十、数据与埋点

### 10.1 SQLite Schema（`~/Library/Application Support/Typetodo/typetodo.db`）

```sql
CREATE TABLE list (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL UNIQUE,
  color       TEXT,
  sort        INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL
);

CREATE TABLE todo (
  id             TEXT PRIMARY KEY,
  title          TEXT NOT NULL,
  due_at         INTEGER,                  -- epoch 秒（UTC），NULL = 无时间
  due_has_time   INTEGER NOT NULL DEFAULT 0,
  list_id        TEXT REFERENCES list(id) ON DELETE SET NULL,
  status         INTEGER NOT NULL DEFAULT 0,  -- 0 pending / 1 done / 2 deleted
  source         INTEGER NOT NULL DEFAULT 0,  -- 0 voice / 1 manual
  raw_text       TEXT,
  audio_ref      TEXT,
  confidence     REAL,
  needs_tidy     INTEGER NOT NULL DEFAULT 0,
  needs_confirm  INTEGER NOT NULL DEFAULT 1,
  batch_id       TEXT,
  dedupe_key     TEXT UNIQUE,
  remind_at      INTEGER,
  snoozed_until  INTEGER,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  completed_at   INTEGER,
  deleted_at     INTEGER
);

CREATE INDEX idx_todo_status_due ON todo(status, due_at);
CREATE INDEX idx_todo_list ON todo(list_id, status);
CREATE INDEX idx_todo_batch ON todo(batch_id);
```

**幂等**：`dedupe_key = "<entry_id>#<index>"`，重试命中唯一键则更新不新建。

### 10.2 埋点

**一期不做联网埋点。** 本地仅记录：创建数、完成数、撤销数、解析失败数，供设置页"使用统计"展示，不导出、不上报。

## 十一、权限与安全

| 权限 | 用途 | 申请时机 | 被拒降级 |
|---|---|---|---|
| 麦克风 | 录音 | 首次触发录音 | 提示去系统设置，功能不可用 |
| 辅助功能 | 焦点判定、粘贴、全局手势 | 首次启动引导 | 听写退化为"仅复制到剪贴板"；捕获仍可用 |
| 通知 | 到点提醒 | 首次创建带时间待办 | 应用内红点 + 设置页提示 |

**安全要求**
- API Key 只写 Keychain（service `app.typetodo.secret`），不落 `config.json`
- 历史文本沿用 AES-GCM 行级加密（前缀 `vpenc1:`），密钥丢失不得覆盖旧密钥
- 日志只记长度与耗时，不记正文
- 非沙盒 App，仅保留麦克风 entitlement；不申请多余权限
- **GPL 合规**：保留上游版权声明、说明修改、整体以 GPL-3.0 发布；不使用上游商标与图标；更换更新签名密钥

## 十二、异常处理清单

| 编号 | 场景 | 期望行为 | 用户可见反馈 |
|---|---|---|---|
| E1 | ASR 失败（网络/额度） | 保留音频进历史，标记可重试 | "识别失败 · 录音已存进历史，可点重试" |
| E2 | 模型返回非法 JSON | 重试 1 次 | 无（静默） |
| E3 | 重试后仍非法 | 原文入库 `needs_tidy` | "已存为待办 · 待整理" |
| E4 | 时间校验失败 | 降置信 + 确认卡 | 确认卡（时间留空） |
| E5 | 数据库写入失败 | 保留在内存队列，下次启动重试 | "保存失败，稍后自动重试" |
| E6 | 通知权限被拒 | 不阻断 | 设置页红点 + 跳转链接 |
| E7 | 用户已用完模型额度（403） | 报错并停止重试 | "额度不足 · 检查 Key 或充值" |
| E8 | 磁盘空间不足 | 停止写音频，仍写文本 | "存储空间不足，已停止保存音频" |
| E9 | 系统时间/时区变更 | 重建通知排程 | 无 |
| E10 | 麦克风被拔出/切换 | 自动切换到默认设备 | 无 |
| E11 | 录音期间进入睡眠 | 丢弃本次并提示 | "录音中断" |
| E12 | 手掌/误触（<0.55s） | 不触发 | 无 |
