## 6. 环境与工具链的坑（每条都是真踩过的）

### 6.1 必须用 Apple Development 重签，否则权限每次编译都丢

ad-hoc 签名的 designated requirement 是 `cdhash`，随二进制变化；TCC 授权绑在
requirement 上，于是**每次重编辅助功能授权就失效**，系统设置里还会堆一串同名条目。

`scripts/sign-dev.sh` 用 Apple Development 证书由内到外重签（Sparkle XPC → 辅助工具 →
框架 → `Typetodo.debug.dylib` → app），签完 requirement 变成
`identifier + certificate leaf`，与二进制内容无关。

**不要加 `--options runtime`**：Debug 构建的主逻辑在独立 `Typetodo.debug.dylib` 里，
硬化运行时的库校验要求 Team ID 一致，只签外层会启动即崩
（`Library not loaded: @rpath/Typetodo.debug.dylib`）。

### 6.2 加文件必须改 pbxproj

工程用**显式文件引用**，不是 Xcode 16 的自动同步组。新增 `.swift` 必须
`python3 tools/add_source_file.py app/Sources/xxx.swift`（负责 BuildFile / FileReference /
Group / Sources 阶段四处）。

脚本里定位组用的是「行首两个 tab + ID」，因为 pbxproj 里**组引用是四个 tab**，
用 `index("ID")` 会命中引用、把文件挂到错误的组下。

### 6.3 跨文件搬代码要提可见性

`fileprivate init` 搬走后调用方看不到，编译报的是极具迷惑性的
`extra arguments at positions #1, #2, #3 in call` + `missing argument for parameter 'coder'`
——实际是「找不到这个 init，退化去匹配 `init?(coder:)`」。

### 6.4 macOS 27 改了权限面板名字

「辅助功能」并入**「设备控制和数据访问」**（`SecurityPrivacyExtension.applex` 里
`ACCESSIBILITY = "Device Control and Data Access"`）。深链
`?Privacy_Accessibility` 仍落在同一面板，**URL 不用改，改文案**。

### 6.5 授权卡住的完整故障链（已修，但要知道原理）

1. 只 `open` 系统设置面板**不会**把 App 登记进列表；登记动作是
   `AXIsProcessTrustedWithOptions(prompt: true)`。
2. 引导期间 `updateAccessibilityDependentFeatures` 会跳过系统弹窗
   （"onboarding owns the prompt"），两条路都不登记 → 列表里永远没有本 App。
3. TCC 里的旧记录会绑在旧签名上：开关是蓝的、`AXIsProcessTrusted()` 恒 false、
   重启无效。唯一解是在列表里**点「−」删除后重新添加**。
   `tccutil reset` 在本机沙箱里跑不通（exit 77）。

### 6.6 网络

会话注入的 `HTTP_PROXY` 端口每次不同且经常失效；系统代理 `127.0.0.1:7897` 可用。
git push 用：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 \
  -c http.version=HTTP/1.1 push origin main
```

### 6.7 沙箱限制（影响自动化验证）

- 直接跑 `Typetodo.app/Contents/MacOS/Typetodo` 会被拦：
  `sandbox_extension_issue_file_to_process failed`，`dangerouslyDisableSandbox` 也解不开。
- `node_repl`（Codex Computer Use）在沙箱内起不来：`sandbox-exec: sandbox_apply: Operation not permitted`。
- `swift test` / `xcodebuild` 需要 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`
  （`tools/xcodebuild.sh` 已封装）。

## 7. 未完成项：UI 验收快照

**目的**：让 AI 能在**不碰用户桌面**的前提下做 UI/UX 验收——不弹窗、不抢焦点、
不要屏幕录制权限、不拍用户其它窗口。

**为什么需要**：之前靠 `open` 打开设置窗 + `screencapture` 整屏截图，
被用户明确指出「争夺控制权」。

**已实现**（`c35a28d`，仅 DEBUG 编译）：

- `SettingsWindowController.debugSnapshot(pages:to:)`：用 `NSView.cacheDisplay` 离屏渲染
  PNG，并 dump 每个 `NSTextField` 的 `x/top/w/h/needW/truncated`
  （`truncated = needW > w + 0.5 && 单行`，用来抓「文案被压断」）
- `UIDebugSnapshot`：入口 + 触发（命令行 `--ui-snapshot` 或 `~/.typetodo-ui-request` 文件）
- `AppDelegate` 在 DEBUG 下启动 1.5 秒轮询的 watcher

**卡在哪**：触发文件写进去后**没有被消费**，`/tmp/typetodo-ui-trace.log` 里没有 trace，
说明 `startWatcher()` 疑似没被调用到。

**下一步定位方法**（一次构建即可分辨）：

1. 在 `UIDebugSnapshot.startWatcher()` 开头加一行 `trace("watcher started")`
2. 若没有该行 → 检查 `applicationDidFinishLaunching` 是否有早退分支，
   或把调用移到 `applicationWillFinishLaunching`
3. 若有该行但文件不消费 → 检查 `FileManager.fileExists(atPath: requestFile.path)` 的路径解析

**已知不能用触发方式的路径**（别再试）：

- 直接跑二进制 → 沙箱拦
- `open -n App --args --ui-snapshot ...` → 参数进不去（被已有实例吃掉）
- 冷启动新进程做快照 → 首次读钥匙串弹授权框并**阻塞**（曾挂死两个进程）

## 9. 工作方式约定（前任与需求方的默契）

1. **先出方案再动手**：代码变更前先给方案，等确认。
2. **一页一提交**：重构不允许「搬家 + 改逻辑」混在一个 commit。
3. **推送前确认**：remote 只有 `main`，push 前必须得到显式许可。
4. **文档与代码同步**：行为或安全变更后必须同步修文档。
5. **批量操作先给预览**：删除、迁移、配置变更前列清单。
6. **不抢用户桌面**：不 `osascript activate`、不擅自开系统面板、不擅自截屏；
   需要 GUI 操作时输出步骤让用户自己做。
